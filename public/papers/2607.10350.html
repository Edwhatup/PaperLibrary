ABot-AgentOS: A General Robotic Agent OS with Lifelong Multi-modal Memory

No notes on this paper yet — it's on the reading list.

Audio digest (电台)

Abstract

Recent VLM and VLA systems have improved robotic perception and action prediction, yet long-horizon embodied agents still require a general runtime layer for reasoning, memory, tool use, verification, and cross-embodiment execution. We present ABot-AgentOS, a general robotic Agent Operating System that sits above low-level controllers and provides a deliberative agent layer for scene-conditioned planning, context-isolated skill execution, multi-stage verification, multi-modal memory, and edge-cloud collaboration. To evaluate such systems, we introduce EmbodiedWorldBench, an executable benchmark with 16 indoor, outdoor, and hybrid scenes, four difficulty levels, and over 200 tasks involving navigation, object search, NPC dialogue, dynamic events, and trace-grounded scoring. ABot-AgentOS further introduces Universal Multi-modal Graph Memory, a persistent source-grounded substrate that converts dialogue, visual observations, spatial context, temporal relations, and task traces into typed nodes and edges. A failure-driven self-evolution loop converts diagnosed memory failures into gated runtime evo-assets that are promoted only to later evaluation splits, preventing current-split ground-truth leakage while enabling continual improvement. On an initial EmbodiedWorldBench subset, ABot-AgentOS improves over a single-controller baseline in both task success and goal completion. Across memory benchmarks, ABot-AgentOS Static achieves 87.5 on LoCoMo, 59.9 on OpenEQA EM-EQA, 88.6 on Mem-Gallery, and 76.5 Acc@All on NExT-QA; self-evolution further improves LoCoMo to 88.7, OpenEQA to 60.4, and Mem-Gallery to 89.0. These results suggest that a general Agent OS layer can improve long-horizon embodied execution while providing persistent, auditable memory for continual interaction.

Chinese digest · 导读全文

机器人要真正走进现实世界，面临的核心难题不是感知，也不是单步动作预测，而是怎样把高层的语义推理可靠地转化成跨越多个步骤、多个场景、持续很长时间的物理执行。这篇论文要解决的就是这个问题。它提出的系统叫做ABot-AgentOS，一个通用的机器人智能体操作系统，同时配套推出了一个可执行的评测基准EmbodiedWorldBench，以及一套叫做Universal Multi-modal Graph Memory的终身多模态记忆机制。

我们先来说清楚这个问题到底难在哪里，以及现有工作留下了哪三个关键缺口。

第一个缺口叫做推理执行鸿沟。现在很多基于视觉语言模型的机器人系统，要么把模型输出直接映射成动作，要么依赖一个整体式的流水线，中间没有一个专门负责任务分解、工具调用、技能委派、验证和恢复的智能体层。模型说"我已经走到目标位置了"，但实际上机器人可能撞墙了，或者根本没动，这种语言层面的信念和物理世界的实际状态之间的断裂，就是这个鸿沟的本质。

第二个缺口叫做跨本体泛化鸿沟。大多数机器人智能体系统和特定硬件、特定控制接口绑得很死，换一个机器人形态，比如从双足人形机器人换成四足狗，整套系统就要重来，成本极高。

第三个缺口叫做持久化具身记忆鸿沟。短期缓冲区、纯文本缓存、或者针对单一任务的记忆模块，没办法可靠地跨越长时间交互来保存多模态的、关系型的、有出处可追溯的经验。机器人今天见过你，明天就不认识了；它上午在某个位置看到一个物体，下午再被问起时，记忆里什么也没有。

为了填补这三个缺口，论文提出了ABot-AgentOS这套架构。

整个系统的设计理念是一个分层解耦的认知运行时。它坐在低层控制器的上面，下面是各种硬件和底层运动控制，上面对接视觉语言大模型，中间这一层就是AgentOS本身，负责推理、记忆、工具使用、验证和跨本体执行。

在硬件适配层面，系统把机器人能力抽象成一个统一的技能与工具层，包括操作技能、导航技能、运动控制、视觉感知以及其他可扩展工具。同一个高层推理逻辑，插入不同的本体接口，就可以驱动人形机器人、四足狗、移动操作臂等不同形态的机器人，而不需要重写上层认知逻辑。这就解决了跨本体泛化的问题。

在计算架构层面，系统采用边缘与云端协同的双LLM设计。边缘侧运行一个轻量的小模型，每个交互轮次都在本地跑，处理低延迟的感知、指令理解、状态跟踪和常规决策。当任务需要复杂推理、长程规划或者消歧义时，系统才按需请求云端的大模型介入。这种路由策略不是写死的规则，而是从训练样本和执行反馈中学习出来的，能判断哪些请求可以在本地可靠完成，哪些需要上云，从而在延迟和成本之间取得平衡。

现在说系统最核心的部分，也就是智能体控制框架，论文叫做Agent Harness。

这个框架把通常被塞进一个控制器的三个角色明确分开：主LLM、技能执行器Skill Runner、以及验证器Verifier。

主LLM是语义规划者。它接收用户指令，结合当前场景信息、地图记忆、机器人状态、近期历史和可用技能，形成一个高层执行计划，并明确写出什么条件算作任务完成。这个规划是场景条件化的，同样一句话"去找红色夹克的老人"，在不同的楼层、不同的探索进度下，需要的执行策略完全不同。主LLM不负责每一步低层移动，它只维护全局任务状态，决定什么时候该直接调工具，什么时候把一个多步子任务委托给技能执行器，什么时候任务可以结束。

技能执行器Skill Runner负责需要持续局部执行的子任务。一个技能不是单次工具调用，而是由一个技能级子智能体在隔离的局部上下文里执行的，这个上下文包括子目标、近期观察、技能状态、失败历史和恢复策略。主LLM收到的是压缩后的技能进展和结果摘要，而不是全部的中间动作序列。

为什么要做这个上下文隔离？在长程具身任务中，局部执行可能涉及反复移动、观察、重新定位、视角调整和碰撞恢复。如果每一次短距离移动、每一次失败尝试都往主LLM的上下文里追加，全局目标很快就会被局部细节淹没。Skill Runner把这个局部复杂性吸收掉，只把对高层阶段管理有用的信息返回给主LLM。

验证器Verifier解决的是语言层面信念和环境真实完成状态之间的不匹配。在数字任务里，成功信号通常是明确的，比如测试通过、API返回成功、页面状态改变。但具身任务里往往没有这样的外部信号，机器人宣称任务完成了，但可能只是模型相信完成了，而不是真的完成了。

验证分三个阶段。运行时验证监控近期轨迹和技能状态是否在有效推进，还是出现了停滞、反复碰撞、局部循环或者与当前计划不符的行为。技能级验证检查委托的子任务是否真正满足了语义目标，而不是因为工具或子智能体正常返回就接受成功。完成时验证在主LLM尝试终止任务时触发，它评估原始指令、当前计划、执行历史、技能摘要、观察结果以及交互过程中引入的任何新要求，然后才允许任务结束。

这三层验证的组合意味着AgentOS不是在最后才检查有没有做对，而是把验证作为整个执行循环内部持续的监督信号，把缺失的完成条件及时反馈回推理层，大幅减少了长程具身任务中的停滞、误判和过早终止。

接下来说记忆系统，这是整篇论文技术贡献里最重头的部分。

论文提出了Universal Multi-modal Graph Memory，一个持久化的、有信息来源可追溯的多模态记忆图。它把对话、视觉观察、空间上下文、时间关系和任务轨迹转化成有类型的节点和边存储起来。

为什么是图而不是普通的文本检索？普通的检索增强生成主要是按语义相似度返回文本片段，它无法回答"这个物体上次在哪儿看到的""两件事情哪个先发生""这只狗和上次遇到的是不是同一只"这类问题，因为这些问题依赖的是实体、时间、地点和关系之间的结构性联系，而不是字面相似度。图记忆先找到相关的种子节点，再沿着有类型的边扩展到局部证据子图，让智能体可以基于结构化证据而不是参数记忆来回答关于位置、身份连续性、相对时间的问题。

图里有什么？节点包括来源容器、证据单元、实体、地点、会话和语义事件几种类型。边编码具身召回所需的关系，包括时间顺序、包含关系、观察关系、参与关系、位置关系、身份连续性、空间关系和交互关系。每个节点存储一个紧凑的JSON格式信息字段，包含来源引用、时间参考、证据摘要、置信度和溯源信息。溯源信息记录了这个节点来自哪次观察、哪段视频、哪一帧、哪次会话，以及是用什么模型提取的。这让每一条记忆都可以被追踪和审计。

关于记忆写入，系统把不同来源的输入归一化成同一种有来源的图式。视频和自中心视觉流产生可见实体、物体状态、地点、动作、帧和事件的语义记录；对话和多模态会话产生会话级和事件级记录，图片附件存为证据节点连接到对应的语义事件。系统优先语义压缩而不是存原始内容，目标是在不牺牲可追溯性的前提下提高信息密度。

举个具体例子。如果用户说"我昨天收养了一只马耳他犬"，系统不是把这句话作为原始文字存进去，而是把它表示成一个时间锚定的语义事件，链接到话语本身、解析后的时间上下文、身份假设、置信度估计和来源证据。如果同时附了一张照片，图片节点就作为支持性多模态证据连接到这个事件上。这样，后来查询这只狗的相关信息时，检索到的是一个结构化的证据子图，而不是一个孤立的文字片段。

检索的时候，查询被转化成语义检索信号和结构线索，包括实体提及、时间表达、模态类型、地点引用和期望的证据类型。检索器用语义嵌入相似度加词法匹配加元数据过滤加节点类型约束综合排序，找出候选种子节点，再沿着相关类型的边展开到局部证据子图，在固定深度和证据词元预算内完成。最终这个子图被序列化成紧凑的证据上下文，配合检索轨迹注入到智能体的推理上下文中。当证据不足或者自相矛盾时，系统要求回答者报告不确定性，而不是凭空编造答案。

现在说整个记忆系统里最有创意的机制：失败驱动的终身自进化循环。

论文的核心洞察是：长期记忆不应该只靠积累新内容来改进，还必须改进写入、检索、选择和使用证据的整个流水线。否则，即使记忆图越来越大，系统也会反复犯同样的提取错误、检索错误、时间定位错误、视觉帧选择错误或者答案合成错误。

这个自进化机制的设计围绕一个关键约束：防止信息泄露。具体做法是按批次部署，每个批次评估结束之后，系统才分析这个批次的失败案例，把诊断出来的失败转化成候选修复方案，编译成受约束的JSON DSL格式的进化资产。这些资产经过严格的门控验证之后，只被允许用在后续批次，绝对不会用在生成它们的那个批次上。

门控验证的标准是：一个候选资产必须在目标验证子集上提高分数至少达到设定阈值，同时在回归子集上不能让已经可靠的案例降分超过另一个阈值。这确保了每个改进只有在既能修复目标失败模式、又不破坏已有可靠行为的前提下，才会被接受和推进。

被接受的进化资产是可生命周期管理的JSON DSL记录，不执行生成的Python代码。每个资产声明目标层、触发条件、允许的操作、安全约束、溯源、验证结果和版本ID。资产可以针对记忆写入、证据选择、答案合成、视觉帧选择、时间归一化或者适配器级归一化等不同层次。

这样，AgentOS积累了两种形式的终身知识：记忆图里的内容级经验，以及进化资产集合里的流水线级改进。

内存系统还有一个边缘云协同的隐私管理层。机器人在边缘侧保存私有记忆，包含所有本地感知到的内容，比如地图、语义信息、多模态交互历史、用户偏好。云端维护公共记忆，只包含低敏感度的公共环境信息，比如路障、施工区域、导航地标。每个新生成的记忆项在同步之前都要经过隐私判断。包含或关联到个人身份信息的内容，比如人脸、姓名、个人物品，判定为不可分享。论文报告在专用数据集上，隐私分类和上传决策的准确率超过99%。

接下来说评测基准EmbodiedWorldBench。

现有具身AI基准大多有三个问题：一是室内室外分割评测；二是只测一种能力维度，要么只测导航，要么只测操作；三是静态评测，没有动态事件，测不了自适应重规划能力。

EmbodiedWorldBench覆盖16个可执行场景，横跨室内、室外和混合设置，包括医院、博物馆、超市、郊区住宅等，共超过200个任务，分四个难度等级。每个评测案例都是一个完整的可运行世界，由空间地图、初始状态、观察规则、NPC行为和成功标准五个要素定义。

论文给了一个具体例子来说明基准的设计思路。给定一个复合指令，智能体需要在一个单独的情节里依次完成四个子目标：检查一条街道、检查后院的游泳池、核实室内电器状态、然后返回报告。这个任务路径穿越了室外街道、住宅后院和室内起居室，同时测试了跨场景导航、NPC交互、环境感知和信息汇报，而不是孤立地测一个技能。

难度分级不是简单地看场景数量或NPC数量，而是考虑空间探索范围、程序长度、交互复杂度、证据要求和动态适应需求，用人机协作标定。系统对信息可见性有严格隔离：智能体只能看到过滤后的语义地图和自然语言指令，NPC位置、评分信号、预期轨迹全部对智能体不可见。

评测指标有两个。任务成功率TSR要求所有子任务目标和终止条件全部满足，是最严格的整体度量。目标完成率GCR是满足的子任务目标比例，提供更细粒度的部分完成情况，反映导航、NPC对话交互和多阶段推理各个维度的表现。

现在说实验结果。

在EmbodiedWorldBench的初始子集上，ABot-AgentOS相比单控制器基线，在任务成功率和目标完成率两个指标上都有提升，验证了增加智能体层的价值。

在记忆基准测试上，结果更具体。ABot-AgentOS Static在LoCoMo上达到87.5分，在OpenEQA EM-EQA上59.9分，在Mem-Gallery上88.6分，在NExT-QA的Acc@All上76.5分。加入自进化之后，LoCoMo提升到88.7，OpenEQA提升到60.4，Mem-Gallery提升到89.0。虽然每个指标的绝对提升幅度看起来不大，比如LoCoMo从87.5到88.7，但这里真正重要的意义在于：这是在不使用当前分批数据进行训练的严格无泄露约束下实现的持续提升，证明了这套自进化机制在跨批次长期部署场景中确实有效，而不是某种数据集过拟合的假象。

论文还介绍了一套面向部署的小模型训练流水线，这部分因为涉及商业部署，结果没有公开，但方法思路值得了解。

核心逻辑是把强教师智能体在文本化具身沙盒环境里的长程工具使用行为蒸馏到一个小的部署模型。沙盒环境把任务指令转化成有状态的沙盒实例，包含环境状态、失败触发条件和人类NPC角色定义。难度分三级，简单场景强调任务分解和基本技能选择，中等场景引入可恢复的障碍，困难场景需要多轮交互、持续目标跟踪和从多重嵌套失败中恢复。

教师模型在沙盒里产生ReAct风格的交互轨迹，不仅包含成功执行，也包含失败尝试、求助行为、重试和恢复步骤，这些都是训练小模型具备鲁棒性所必需的数据。轨迹经过LLM-as-a-Judge过滤后用于监督微调，然后再通过在线强化学习进一步提升。

强化学习采用GiGPO算法，对同一初始沙盒状态采样多个展开，通过比较同一场景下不同展开的合并回报形成情节级相对优势，同时比较对齐或可比决策步骤的步骤级奖励形成步骤级相对优势，最终结合两个层次的相对比较来更新策略。奖励由一个自进化的LLM-as-a-Judge奖励引擎提供，同时输出步骤级和情节级信号，减少长程轨迹中的信用分配困难。这个奖励引擎本身也有一个元级别的验证层来检查奖励的可靠性，并把低质量的判断案例转化成局部提示更新，让奖励提示随着技能、任务和智能体行为的变化而持续改进。

现在来说这篇工作的局限性和对你工作可能的启发。

局限性方面，论文自己承认EmbodiedWorldBench目前的规模相对有限，16个场景200多个任务，还需要在更大范围的多样化场景上验证。记忆图的维护在极长时间跨度下的可扩展性尚未充分验证。自进化机制目前主要在记忆流水线的JSON DSL层面运作，还没有扩展到技能本身的改进。真实物理部署的结果因为商业原因没有公开，系统的物理世界鲁棒性还需要更多验证。

对于做具身智能或智能体系统研究的人，这篇工作有几个具体可借鉴的点。

第一，智能体层三角分离的设计模式非常值得参考：把语义规划者、局部执行者和验证者明确分开，上下文隔离是处理长程具身任务中过早终止和语言执行不一致问题的有效工程手段。第二，多模态记忆设计不应该是把原始内容堆在一起，而应该是语义压缩加上可追溯的来源图，这样检索才能做关系推理而不只是相似度匹配。第三，失败驱动的自进化机制加上严格的无泄露门控，是让系统在部署过程中持续改进而不引入数据污染的关键设计，这个约束本身比进化算法本身更重要。第四，评测基准的设计理念值得借鉴：单情节多能力联合测试，加上严格的信息隔离和轨迹溯源评分，比分能力维度的静态数据集更能反映真实的长程智能体能力。

把高层语义推理和持久化多模态记忆放在一个统一的智能体运行时里，通过验证闭环和失败驱动自进化让系统在长期交互中不断收敛，这是让机器人从实验室原型走向可靠现实部署必须要迈过的工程台阶。
