# DanceOPD: On-Policy Generative Field Distillation

> 现代图像生成模型正面临一个核心挑战：我们期望一个模型能够同时拥有多种强大的功能，比如根据文字描述生成图像、对图像进行局部修改，以及进行全局性的风格或布局编辑。然而，这些能力在实际应用中往往难以兼容，甚至会相互冲突。举例来说，为了实现更精细的

**摘要 (EN):** Modern image generation demands a single model that unifies diverse capabilities, including text-to-image (T2I), local editing, and global editing. However, these capabilities are rarely naturally aligned and often conflict. For instance, editing tends to degrade T2I performance, while global and local editing interfere with each other. Consequently, effectively composing these capabilities has become a central challenge for image generation model training. To tackle this, we introduce DanceOPD, an on-policy generative field distillation framework for flow-matching models that routes each sample to one capability field, queries one low-noise student-induced state, and trains with a simple velocity MSE objective. With each capability source defined as a velocity field over the shared flow state space, the student learns from fields queried on its own rollout states to compose expert capabilities. This formulation also absorbs operator-defined fields such as classifier-free guidance. Comprehensive experiments on T2I, editing, realism-field absorption, and CFG absorption show that our approach improves multi-capability composition, strengthening target capabilities while preserving anchor generation quality. We believe this work establishes a practical route for generative field distillation in flow-matching models.

## 笔记
- (2026-06-28) 批判性备注：'增强目标能力+保持锚定能力'这点，论文只做了实验演示(demonstrated)，未给理论证明(why必然能)。作者自己声明不主张全局帕累托最优，只是操作性地定义了'目标区域'再用实验+消融(硬路由>软混合3.6~4.3%等)支撑。其'为什么能保住锚定'是机制合理性论证(硬路由使T2I样本信号不被稀释、冻结teacher作稳定锚点、组合在跨更新的统计意义上发生而非单样本内平均冲突梯度)，属plausibility而非proof。
- (2026-06-28) 【基础概念】速度场=空间每个状态/时刻上的一个箭头(速度向量)，告诉你'下一步往哪走多快'；模型本身就是这个场。rollout=拿当前参数真的从噪声一步步照箭头走一遍生成；轨迹=走出来的中间状态序列。生成是迭代的(预测下一步)，所以才有'轨迹'。
- (2026-06-28) 【两层循环+成本】外层=很多训练step，每个样本要重跑一次学生rollout(这是on-policy的固有代价，off-policy可直接给数据图加噪、无需生成)；内层=一条轨迹有几十去噪小步但只在低噪声点问老师1次(单次查询)。所以'很多次rollout'(外层)真，'一条轨迹内多次查询'假。rollout用stop-gradient(纯前向、不反传整条求解器)+flow少步采样把代价压住。
- (2026-06-28) 【提问→优化】提问=在状态x_t问被硬路由选中的那一个老师，拿到目标速度向量v_k(stop-gradient,当标签)；优化=学生在同一点预测自己速度v_S(θ)，loss=‖v_S−v_k‖²(速度MSE回归)，梯度下降把学生这点的箭头掰向老师的箭头。本质是普通监督回归，标签=老师在该状态的速度。组合能力靠跨样本统计:不同区域被不同老师塑形，硬路由保证单次更新只认一个老师→无折中向量内耗。
- (2026-06-28) 【批判·能力上限】核心目标只有速度MSE一项:只向老师学、不向真实数据学、无独立质量项(GenEval/GEditBench仅评测不进loss)。数据ground-truth搬家到了(a)学生基底模型初始化(b)老师本身是数据训出的专家。后果:DanceOPD能力天花板被老师锁死，是'格局的寄生者'——没好老师就蒸不出东西；偶尔略超单老师只是把已有老师榨更干净(on-policy+组合)，非创造老师之外的新能力。印证'母题随底座变强而失效'。

## 问答记录
- **Q** (2026-06-28): 我的理解是不是对的：DanceOPD 是在生成视频时用多个 teacher 指导不同情况下的生成？
  **A:** 方向对了一半。修正：(1) 是图像生成(T2I/局部+全局编辑/真实感/CFG)，不是视频。(2) 确实有多个teacher(能力场)、且每个样本硬路由到唯一一个场学习(非平均混合)；但论文真正的创新是'在策略(On-Policy)蒸馏'——teacher是在【学生自己生成的轨迹】的低噪声状态点上、每样本只查询一次，从而消除训练/推理状态分布不匹配，并把多种能力无冲突地内化进【单一】部署模型。即重点不在'有多个老师'，而在'在学生自己的rollout上、低噪声处问一次老师'。消融:硬路由>软混合(+3.6~4.3%)、低噪声>中/高噪声查询(+3.2~4.4%)、单次>密集查询。
