# EnterpriseClawBench: Benchmarking Agents from Real Workplace Sessions

> 我们今天聊的这篇论文，它要解决的核心问题是：当前的大语言模型（LLM）正在从我们熟悉的文本助手，逐步演变成能够在真实工作环境中自主操作的“智能体”或“代理”（agent）。这些智能体不再仅仅是生成一段文字，它们需要真正进入到我们的工作空间里

**摘要 (EN):** Enterprise agents increasingly operate inside workspaces: they read heterogeneous files, invoke tools, and deliver business artifacts. We introduce EnterpriseClawBench, an enterprise agent benchmark constructed from proprietary, real-world agent sessions. Starting from a large archive of workplace sessions, the EnterpriseClawBench produces 852 reproducible tasks, each paired with recovered fixtures, rewritten prompts, role classes, skill subclasses, hard rules, and semantic rubrics. Because the sessions contain internal enterprise content, we do not release the benchmark data; instead, our reusable contribution is the construction and evaluation protocol. On EnterpriseClawBench, the best configuration reaches only 0.663 (Codex with GPT-5.5). These results show that enterprise agent evaluation must report harness--model combinations, artifact delivery, visual quality, cost, runtime, and skill-transfer behavior, rather than collapsing performance into a single score. ## 问答记录
- **Q** (2026-06-29): 这论文简单说就是把一个公司的工作记录抽象成 dataset 了？还有什么亮点？
  **A:** 概括抓住了数据来源但漏了核心:因为真实企业数据含敏感信息【不公开】,论文真正可复用的贡献不是dataset而是【构建协议+评估协议】(给渔不给鱼)。亮点:①自动化构建流水线把噪声会话炼成可复现任务(5291原始→852个),含机械门槛:长度过滤/夹具(fixtures)恢复/脱敏恢复/网络依赖/自包含性判断→重写单轮prompt+分类(7角色类→45技能子类)+硬规则+语义评分+沙盒预检。②评估的是【harness(爪子)×model组合】而非只评基座,最好Codex+GPT-5.5仅0.663,远未饱和。③关键发现:harness与模型会'水土不服'——Claude系在Hermes下从0.62~0.64暴跌到0.458,因运行时不匹配(Hermes审批门槛挡住Claude的主动探索/自修复,且在写产物前截断痕迹)→启示:必须报告爪子+模型组合。④分层评分:硬规则(客观)+LLM语义5维(接地准确/相关/深度/实用/沟通),按模态路由(表格PPT给视觉评审),但视觉评审给表格PPT系统性偏高→暴露多模态评审器校准不如文本评审器。其他结论:最弱是'接地准确性'(大文件里丢信息);市场/财务任务最难;成本-得分呈对数曲线(边际递减)。
